# Learning loop (end of every run, unasked, keep it short)

The workflow gets better with each video because choices are logged and promoted to defaults.

1. **Append one row** to `video-workflow/style-history.md` per run: run id, the variants the user picked, notes, mode switches (MEDIA↔MOTION). Accepted stars count as picks. Do not re-read old rows during a run.
2. **Promote** anything chosen twice (for the same kind of beat) to "Current defaults" in **both** `style-preferences.md` and `BRIEF.md`, with the date. A mode switch made twice for the same kind of beat edits the routing rule notes in `style-preferences.md`.
3. **b-roll outcomes**: record approved and rejected candidates and why, so the next sourcing pass skips them.
4. **QA flags**: if automated checks or the critic flagged the same thing twice, add one line to `BRIEF.md`'s fixed rules so builders avoid it up front.
5. **Retro**: three lines at the end of `script.md` (what worked, what the user changed, what to try next).

Keep `style-preferences.md` short (a page). The per-pick history lives in `style-history.md`, which is append-only and never read during a run.

## Watching list
A choice made once goes to a "Watching" section in `style-preferences.md`. If it repeats, promote it.
